# Monitoring & Logging

## Three signals

| Signal | Source | Pipeline | Where to look |
|--------|--------|----------|---------------|
| **Logs** | winston JSON on stdout (one line per request + errors with stack) | Docker → Alloy → Loki | Grafana logs panels / Explore; `az containerapp logs show` in prod |
| **Metrics** | `prom-client` at `GET /metrics`, postgres-exporter | Prometheus (15s scrape) | Grafana dashboard |
| **Health** | `/health`, `/health/live`, `/health/ready`, `/healthz` | Docker HEALTHCHECK, compose, Container Apps, CI | `docker compose ps`, SPA `/status`, CI smoke test |

## Log format

```json
{"level":"info","message":"request","method":"POST","path":"/api/posts","route":"/api/posts/",
 "status":201,"duration_ms":48,"requestId":"87ea…","userId":6,"service":"blogflow-api",
 "timestamp":"2026-10-29T05:01:45.351Z"}
```

- `requestId` is returned to the client as `X-Request-Id` (nginx forwards its own `$request_id`),
  so a user-reported error can be traced to its log line.
- Level is `error` for 5xx, `warn` for 4xx. Health/metrics probes are not logged.
- Alloy promotes `level` to a Loki label → `{service="backend", level="error"}` is a cheap query.

## Metrics

| Metric | Type | Labels |
|--------|------|--------|
| `http_requests_total` | counter | method, route, status |
| `http_request_duration_seconds` | histogram | method, route, status |
| `db_pool_connections` | gauge | state = total / idle / waiting |
| `process_cpu_seconds_total`, `process_resident_memory_bytes`, `nodejs_heap_*`, `nodejs_eventloop_lag_*` | default | — |
| `pg_up`, `pg_stat_database_numbackends` | postgres-exporter | datname |

`route` is the Express route **pattern** (`/api/posts/:id`), never the raw URL, so label
cardinality stays bounded.

## Dashboard — *BlogFlow — Service Overview*

Provisioned from [`monitoring/grafana/dashboards/blogflow.json`](../monitoring/grafana/dashboards/blogflow.json)
(generated by `node monitoring/grafana/build-dashboard.mjs`).

| Requirement (brief) | Panel(s) |
|---------------------|----------|
| Request rate and latency | *Request rate* stat, *Request rate by route*, *p95 latency* stat |
| Error rate | *Error rate (5xx)* stat, *Responses by status class* |
| CPU / Memory usage | *API CPU usage*, *API memory* (RSS + heap) |
| Database connections | *API DB pool connections*, *Postgres active connections*, *Database* status |
| Response time percentiles | *Response time percentiles* (p50 / p95 / p99) |
| (extra) | API status, uptime, event-loop lag, warn/error logs, all container logs |

An `Environment` variable switches between `local` and `production` once the prod scrape job is enabled.

## Alerting

Defined twice on purpose — Prometheus rules (visible at http://localhost:9090/alerts) and
Grafana-managed rules that notify a webhook (`ALERT_WEBHOOK_URL` — Slack/Discord/Teams):

| Alert | Condition | Severity |
|-------|-----------|----------|
| BackendDown | API scrape failing ≥ 1 min | critical |
| DatabaseDown | `pg_up == 0` ≥ 1 min | critical (Prometheus) |
| HighErrorRate | 5xx > 5% for 5 min | warning |
| HighLatencyP95 | p95 > 500 ms for 5 min | warning |
| HighMemoryUsage | RSS > 400 MB for 10 min | warning (Prometheus) |
| DbPoolSaturated | queries waiting for a connection ≥ 2 min | warning (Prometheus) |

Test it: `docker compose stop backend` → BackendDown fires after ~1–2 min → `docker compose start backend`.

## Monitoring production

1. Save the API's `METRICS_TOKEN` (a Container Apps secret) into `monitoring/prometheus/prod-token` (gitignored):
   `az containerapp secret show -n blogflow-api -g blogflow-rg --secret-name metrics-token --query value -o tsv`
2. Uncomment the `blogflow-api-prod` job in `monitoring/prometheus/prometheus.yml`.
   Scraping keeps the scale-to-zero API awake, so enable it while demoing rather than permanently.
3. `curl -X POST http://localhost:9090/-/reload`
4. Select `production` in the dashboard's Environment dropdown.

Production logs (JSON lines, live stream):

```bash
az containerapp logs show -n blogflow-api -g blogflow-rg --type console --follow
```

For retained, searchable logs attach a Log Analytics workspace to `blogflow-env`, or ship them to
Grafana Cloud Loki; neither is enabled to keep production at ~$0/month.
